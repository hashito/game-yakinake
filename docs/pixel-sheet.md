# 作品別の制作シート

企画時にこのシートを作品フォルダへコピーする。最初の一室で決めた数値と画像を保存し、以後の外注・生成・実装で同じ見本を使う。下の値は止水ハンドルの記入例。

## 1　画面と原画

## 2　アイテム一件の記入例

| 項目 | 制作時の指定 |
|---|---|
| 対象と置き場 | `valve_wheel`、ポンプ室の作業台。外径24cm、厚み3cmの可動小物。台の天面に寝かせる。 |
| 発見時に読む形 | 入口から約3mでは卓上に輪があると分かる。近寄ると三本の腕と白い巻き布を確認できる。壁の棚に同じ形の飾りを置かない。 |
| 手元で読む事実 | 中心の四角穴に角軸が入る。調査写真では穴の四辺と奥を写す。プレイヤーはバルブ側の形を見比べて判断できる。 |
| 所持品と写真 | 一覧には32×32の全形。調査には軸穴が正面寄りに見える専用カット。写真に添える観察文は「真ん中に四角い穴が開いている」。感想欄には「白い布のところだけ、やけに手になじむ」。 |
| 操作と状態 | 台の上→所持→軸に取り付け→閉栓。所持中だけ使用可能。取り付け後は所持欄から外す。閉栓時に巻き布が回り、止まる位置と水音が変わる。再開時に同じ位置から拾い直せないこと。 |
| 裏設定の出し方 | 以前の係員は手袋でも握る位置が分かるように、一か所だけ布を巻いた。布の縁の汚れは指が触れる面に集める。気付かなくても閉栓できる。 |
| 置き直す判断 | 立った位置から手前の私物に隠れて輪が読めない場合、先に作業台を整理する。操作距離やカメラの画角は共通設計に合わせる。 |



## 3　全アイテム監査

作品内のアイテムと近距離小物を `pixel-items.json` に列挙する。拾える物は world / inventory、調べられる物はさらに examine を必須にする。3D現物の world もドット絵表現であり、通常画像や写真のままにしない。制作途中と公開前に `node pixel-workshop/audit-items.mjs <作品のpixel-items.json>` を実行し、0件の欠落を確認する。詳細は [全アイテムのドット絵化ルール](pixel-style.md)。

## 4　素材台帳に追記する欄

対象ごとに一行を複製する。「実ファイル」には、作品が読み込むファイル名またはモデルのノード名を記す。調査写真と当時の記録が別の状態を表す場合は、それぞれの状態名を添える。生成や描き直しを依頼するときにもこの行を渡す。

| 対象ID・名前／用途 | 置き場・寸法・可動軸 | 識別点／発見距離・調査距離 | 状態と切替条件 | 実ファイル（3D・一覧・調査） | 原画・出典・利用条件 | 担当・検収票の行 |
|---|---|---|---|---|---|---|
|  |  |  |  |  |  |  |

人物が登場する作品では「待機・移動・働きかけ・結果」のうち使う動作を列挙し、形が変わる瞬間とゲーム上の時刻を対にして台帳へ書く。左右差のある装具・傷・利き手は、正面と背面の基準絵に同じ物として描き込む。

既存の[制作キュー](media-production.md)と画像制作手順（Game-fleet の docs/image-generation.md）で原画や撮影を手配する。モデルや原画を更新したときは同じIDに結び付く画像を取り直し、検収票（Game-fleet の docs/pixel-art/acceptance.md）に比較結果を記入する。
